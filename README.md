# ML_Permeability4PorousMaterials

Predict permeability tensors of porous materials from microstructure features using neural networks, and inversely design microstructures to achieve a target permeability.

**Pipeline:** 3D porous geometry → LBM fluid simulation → dataset → forward neural network → inverse neural network

## Installation

### Neural Network Module

Requires **Python 3.10+**. A CUDA-capable GPU is optional but recommended.

```bash
cd neural-net
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Dependencies: `numpy>=1.24`, `pandas>=2.0`, `scikit-learn>=1.3`, `torch>=2.0`, `matplotlib>=3.7`, `optuna>=3.4`

### LBM Simulation Module (HPC only)

Requires **Python 3.11+**, a CUDA-capable GPU, and an HPC environment with SLURM.

```bash
cd lbm_simulation
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Dependencies: `lbmpy[gpu]`, `cython`, `pystencils`, `h5py`, `numpy`, `matplotlib`, `scikit-image`, `imageio`

> **Note:** The SLURM job script (`job.sh`) loads specific modules (GCC 12.3.0, Python 3.11.3, CUDA 12.6.0). You will need to adapt these to your cluster.

## Dataset

The file `neural-net/256-final.csv` contains **12,911 samples** with 46 columns. It was generated by running LBM simulations on synthetic porous geometries and merging the results with geometric descriptors.

### Features used by the neural network (11 columns)

| Column | Description |
|--------|-------------|
| `a20`, `a11`, `a02`, `a10`, `a01`, `a00` | Morphological descriptors (Minkowski functionals) |
| `m` | Microstructure parameter |
| `porosity` | Volume fraction of fluid phase |
| `tortuosity_geometric_x`, `_y`, `_z` | Geometric tortuosity in each direction |

### Targets (3 columns)

| Column | Description |
|--------|-------------|
| `K_xx`, `K_yy`, `K_zz` | Diagonal components of the Darcy permeability tensor |

During training, targets are **log10-transformed** (with a floor of `1e-30`) and then **MinMax-scaled** to [0, 1]. Scalers are fit on the training set only.

The data is split **70% train / 20% validation / 10% test** (random seed 42).

## Quick Start

Train the forward model, then the inverse model:

```bash
cd neural-net

# Step 1: Train the forward model (features → permeability)
python train_model.py

# Step 2: Train the inverse model (permeability → features)
python train_inverse_model.py -f forward_model_output/best_model.pt
```

With hyperparameter tuning (recommended for best results):

```bash
# Step 1: Tune + train forward model
python train_model.py --tune

# Step 2: Tune + train inverse model
python train_inverse_model.py -f forward_model_output/best_model.pt --tune
```

## Script Reference

### `model_config.py` — Shared Configuration

This file contains the `CONFIG` dictionary, data loading/preprocessing functions, the `PermeabilityMLP` model class, and training utilities. Both `train_model.py` and `train_inverse_model.py` import from it.

**To change defaults** (learning rate, hidden layers, batch size, etc.), edit the `CONFIG` dictionary in this file. See [Configuration Reference](#configuration-reference) for all options.

**Environment variable:** Set `PERMEABILITY_DATA_PATH` to override the default CSV path:

```bash
export PERMEABILITY_DATA_PATH=/path/to/your/data.csv

```

### `train_model.py` — Forward Model

Trains a neural network to predict permeability (K_xx, K_yy, K_zz) from 11 microstructure features.

#### CLI Arguments

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `--tune` | flag | `False` | Run Optuna hyperparameter search, then train with best params |
| `--tune_only` | flag | `False` | Run Optuna search only (saves best params, skips training) |
| `--params` / `-p` | path | `None` | Load hyperparameters from a JSON file |
| `--data` / `-d` | path | `None` | Path to CSV dataset (overrides config and env var) |

#### Usage Examples

```bash
# Train with default hyperparameters
python train_model.py

# Train with a custom dataset
python train_model.py -d /path/to/custom_data.csv

# Run Optuna HPO (50 trials) then train with the best params found
python train_model.py --tune

# Run Optuna HPO only — saves best params to JSON, does not train
python train_model.py --tune_only

# Train using previously saved Optuna params
python train_model.py --params forward_model_output/optuna_best_params.json
```

#### What Optuna Tunes

| Parameter | Search Range |
|-----------|-------------|
| Number of hidden layers | 2–6 |
| Hidden layer base width | 64–1024 (step 64) |
| Width decay per layer | 0.6–1.0 |
| Dropout rate | 0.0–0.2 |
| Learning rate | 1e-5 to 5e-3 (log scale) |
| Weight decay | 1e-8 to 1e-3 (log scale) |
| Batch size | 64, 128, 256, or 512 |
| Scheduler factor | 0.3–0.8 |
| Scheduler patience | 8–25 epochs |

Optimization target: validation MAE in model space (log10 K). 50 trials with TPE sampler and median pruner.

#### Metrics Reported

Per component (K_xx, K_yy, K_zz) and overall: **R²**, **MAE**, **RMSE**, **NRMSE** (normalized by data range), **MdAPE** (median absolute percentage error).

### `train_inverse_model.py` — Inverse Model

Trains a neural network to predict microstructure features from target permeability values. Uses a **frozen forward model** in the loss function to ensure physical consistency.

**Requires** a trained forward model checkpoint (from `train_model.py`).

#### CLI Arguments

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `-f` / `--forward_checkpoint` | path | *required* | Path to trained forward model `.pt` file |
| `-l` / `--loss_mode` | string | `geometry` | Loss function: `geometry`, `bounding`, or `fwd_only` |
| `--w_param` | float | `0.1` | Weight for geometry reconstruction loss (geometry mode) |
| `--w_bounding` | float | `1.0` | Weight for bounding loss (bounding mode) |
| `--bound_margin` | float | `0.0` | Fraction to expand parameter bounds (bounding mode) |
| `-r` / `--resume` | path | `None` | Resume training from a checkpoint |
| `-o` / `--output_dir` | path | `inverse_model_output` | Output directory |
| `--tune` | flag | `False` | Run Optuna HPO then train |
| `--tune_only` | flag | `False` | Run Optuna HPO only |
| `-p` / `--params` | path | `None` | Load hyperparameters from JSON |

#### Loss Modes

| Mode | Loss Formula | Description |
|------|-------------|-------------|
| `geometry` | `L = w_fwd × ‖FNN(Inv(K)) − K‖² + w_param × ‖Inv(K) − θ_true‖²` | Forward consistency + direct feature reconstruction. Good general-purpose choice. |
| `bounding` | `L = L_fwd + w_bounding × L_bound` | Forward consistency + penalty for predictions outside the training data range. Avoids the averaging artefact of geometry mode. |
| `fwd_only` | `L = ‖FNN(Inv(K)) − K‖²` | Pure forward consistency — no feature supervision. Most freedom for the inverse model. |

Where `FNN` is the frozen forward model, `Inv` is the inverse model, `K` is the target permeability, and `θ_true` is the true microstructure features.

#### Usage Examples

```bash
# Default training (geometry loss)
python train_inverse_model.py -f forward_model_output/best_model.pt

# Bounding loss mode
python train_inverse_model.py -f forward_model_output/best_model.pt --loss_mode bounding

# Geometry mode with custom weight
python train_inverse_model.py -f forward_model_output/best_model.pt --loss_mode geometry --w_param 0.05

# Forward-only loss (no feature supervision)
python train_inverse_model.py -f forward_model_output/best_model.pt --loss_mode fwd_only

# Run Optuna HPO then train
python train_inverse_model.py -f forward_model_output/best_model.pt --tune

# Train with previously tuned params
python train_inverse_model.py -f forward_model_output/best_model.pt --params inverse_model_output/inverse_optuna_best_params.json

# Resume from a checkpoint
python train_inverse_model.py -f forward_model_output/best_model.pt --resume inverse_model_output/checkpoints/inverse_epoch_200.pt
```

#### Design vs Auxiliary Parameters

The inverse model predicts all 11 features internally, but only **8 design parameters** are exported:

- **Design (exported):** `a20`, `a11`, `a02`, `a10`, `a01`, `a00`, `m`, `porosity`
- **Auxiliary (internal only):** `tortuosity_geometric_x`, `_y`, `_z` — needed for forward consistency loss but not useful for design

### `lbm_batch.py` — LBM Simulation

Computes the full 3×3 permeability tensor for a single porous geometry using the Lattice Boltzmann Method. Applies a body force in each of the three directions (x, y, z) and measures the resulting fluid velocity to compute permeability via Darcy's law.

#### CLI Arguments

| Argument | Type | Required | Description |
|----------|------|----------|-------------|
| `--sample-index` | int | Yes | Index of the HDF5 file to process (0-based, from sorted file list) |
| `--input-dir` | string | No | Directory containing `.h5` geometry files |
| `--output-dir` | string | No | Directory for output CSV files |

#### Input Format

HDF5 files with a dataset named `scalar_value` containing a 3D binary array:
- `1` = solid
- `0` = fluid

#### Usage

```bash
# Process a single sample
python lbm_batch.py --sample-index 0 --input-dir /path/to/geometries --output-dir /path/to/results
```

Output: one CSV per sample (`result_{sample_name}.csv`) containing the full K tensor, eigenvalues, convergence info, and porosity.

#### Simulation Settings

| Setting | Value |
|---------|-------|
| Stencil | D3Q19 |
| Method | TRT (Two-Relaxation-Time) |
| Kinematic viscosity (ν) | 1/6 |
| Body force | 1e-5 |
| Max iterations per direction | 150,000 (30 × 5,000) |
| Convergence (relative) | 1e-6 |
| Convergence (absolute) | 1e-10 |
| GPU acceleration | Enabled by default |

### `job.sh` — SLURM Submission

Submits `lbm_batch.py` as a SLURM array job for parallel processing of many geometries.

```bash
sbatch job.sh
```

#### What to Customize

| Setting | Current Value | Where |
|---------|--------------|-------|
| Input directory | `/data/cat/ws/ahkh532h-permeability/data_256/...` | `INPUT_DIR` variable |
| Output directory | `/data/cat/ws/ahkh532h-permeability/LBM_results/256` | `OUTPUT_DIR` variable |
| Array range | `0-5720` (5,721 samples) | `#SBATCH --array` |
| Concurrent tasks | `64` | `%64` suffix on array |
| Partition | `capella` | `#SBATCH --partition` |
| Module versions | GCC 12.3.0, Python 3.11.3, CUDA 12.6.0 | `module load` lines |

Resources per task: 1 GPU, 8 CPUs, 16 GB RAM, 48-hour time limit.

## End-to-End Pipeline

```
Step 1          Step 2              Step 3           Step 4              Step 5
Generate     →  Run LBM          →  Merge into    →  Train forward   →  Train inverse
geometries      simulations         single CSV        model               model
(external)      (lbm_batch.py)      (external)        (train_model.py)    (train_inverse_model.py)
```

1. **Generate porous geometries** (external tool, not included). Output: HDF5 files with binary 3D voxel grids.
2. **Run LBM simulations** using `lbm_batch.py` (via SLURM or manually). Produces one CSV per sample with the full permeability tensor.
3. **Merge results** (external step). Combine per-sample CSVs, add geometric descriptors (Minkowski functionals, tortuosity), and produce a single CSV like `256-final.csv`.
4. **Train forward model**: `python train_model.py --tune`. Learns the mapping from 11 features to 3 permeability components.
5. **Train inverse model**: `python train_inverse_model.py -f forward_model_output/best_model.pt --tune`. Learns to predict microstructure features from target permeability.

> **Note:** Steps 1 and 3 (geometry generation and CSV merging) are not part of this repository. The dataset `256-final.csv` is provided so you can start directly from Step 4.
